# @fundroom/search

Workspace search ("Postgres FTS with ACL filtering and extracted text").

One table, `core.search_entry` (migration `0013_search_portability_i18n.sql`), holds a row per
searchable *part* of an entity: title, plain-text body (extracted PDF text, page sections, update
bodies), the SPA path the hit opens, and an ACL. `tsv` is generated by Postgres
(`setweight(title,'A') || setweight(body,'C')`, `simple` configuration: lower-cased, no stemming,
no stop words). `core.search_state` records which provider version each (workspace, module) was
built with and whether a rebuild was asked for.

**Languages.** `simple` splits words at spaces and punctuation, so languages written with spaces
between words (Latin, Cyrillic, Greek, …) match word by word, exactly as spelled (no stemming:
`deck` does not find `decks` unless typed as the prefix `deck…` in the last position). Chinese,
Japanese and Thai are written without spaces: the parser sees a whole run of such characters as
ONE word, so a body is found only by typing the run from its start (`契約書` finds `秘密保持契約書`
only if that is the whole run or its beginning). Titles get one extra rule: a query containing
CJK/Thai also matches a title that contains it as a substring (`契約` finds the title
`秘密保持契約書`). Body text in those scripts has no substring match — a known limitation.

## What is indexed

Whatever modules contribute. At E2.8: data-room documents (title + extracted text), content pages
and updates posts. Kernel `core.*` facts (people, groups) are not indexed.

## ACL model

Each entry carries one `SearchAcl`:

| kind | who may see it | enforced by |
|---|---|---|
| `members` | every live member of the workspace | RLS |
| `groups` | members with a live membership (`revoked_at IS NULL`) in a live group of `groupIds` | RLS (`core.group_member`) |
| `staff` | staff only | RLS |
| `resource` | holders of `view` on `{resourceKind, resourceId, path?}` | RLS (`core.has_access`, the effective-access mirror) **and** `authz.check` at query time |

Staff see every entry. For an investor the query runs in their own external tenant context, so
RLS admits only what the table above allows; `resource` hits are then re-checked with
`authz.check(principal, resource, "view", requestFacts)`:

- **denied** → dropped;
- **gated** (NDA, accreditation, auth level, IP allow-list) → kept only as a *title* match,
  returned with `gated: true` and `snippet: []` (see "What an investor can learn" below).

All parts of one ref should carry the same ACL; hits are de-duplicated per
(module, kind, refId) *after* the ACL post-filter, keeping the best-ranked admitted part.

### What an investor can learn from search

Exactly what the portal would show them, plus the **titles of documents they are granted but
gated from** (NDA not yet signed, accreditation pending, …), and nothing about those documents'
bodies:

- entries they may open in full: title, a body snippet, `href`, `updatedAt`;
- gated entries: the title, `href` and `updatedAt` — found only when the query matches the
  **title alone** (every word in the title, or a trigram/CJK title match), ranked by the title
  alone. The engine takes gated hits from a separate title-only candidate list and ignores every
  whole-entry (title + body) row of a gated or denied resource; when the whole-entry list hits its
  1 000-row cap before a page is filled it is re-read with those resources excluded, so they
  cannot displace other hits either. So whether a gated title is returned, where it appears, and
  `hasMore` do not change with its body — two queries that differ only in a word of a gated body
  answer identically (integration test `a gated hit never depends on the body`). Residual: a
  re-read is attempted up to 8 times; only past ~3 500 matching not-openable resources could the
  cap fall back to dropping openable hits.
- nothing about entries they may not see at all (RLS: other groups, staff-only, ungranted
  resources, other workspaces): not a title, not a count.

## Query (`GET /api/v1/search`)

`apps/server/src/routes/search.ts` picks the modules the caller may search (enabled, not
switched off by the offering status, not hidden from investors by it — the bootstrap's rules),
applies the rate limit (30 a minute per membership; skipped under view-as, which writes nothing)
and calls `runSearch`:

1. **Parse like the index.** The query is split on whitespace (≤ 12 words, NFC, control
   characters removed); each word goes through Postgres's own parser —
   `to_tsvector('simple', word)`, a bound parameter — so the query gets exactly the lexemes a
   document containing it has: `john.doe@acme.com`, `acme.com`, `report_final.pdf`, `3.5`,
   `$1.5M` (`1.5` + `m`), `Q3-2025` (`q3` + `-2025`), `2025-09-23`, `COVID-19` all match as typed.
   The tsquery is assembled from those lexemes (≤ 32), each a single-quoted literal cast with
   `::tsquery` — never `to_tsquery` — so nothing typed is read as syntax. Lexemes are AND-ed;
   every lexeme of the last word is a prefix (`'pitch' & 'de':*`; a partly typed `Q3-20` still
   finds `Q3-2025`). No lexeme left → 400 `search_query_invalid`.
2. **Candidates** (one read transaction, no bodies read): (a) by the whole entry — full-text
   hits by `ts_rank_cd(tsv, q, 32)` then `source_updated_at`, followed by title-fallback matches
   (`pg_trgm` `word_similarity ≥ 0.4` for queries of 3+ characters; a title substring for
   CJK/Thai) that were not already hits; (b) for investors, `resource` entries by the title alone
   (the gated-hit list, above). At most 1 000 rows each.
3. **Post-filter** with no transaction held (authz reads through its own connection), merge (a)
   and (b) in rank order, de-dup, page with `offset`/`limit`, `hasMore`.
4. **Snippets** (second read transaction) for the page's non-gated hits whose body contains a query
   word: `ts_headline` with `\u0002`/`\u0003` delimiters (MaxFragments 2), split into
   `{ text, highlight }` segments, whitespace collapsed, at most 480 characters. Never HTML; stored
   text has every control character replaced, so a body cannot forge a delimiter.

## How modules contribute

Two halves, both on `ModuleManifest` / `ModuleServices` (`@fundroom/module-kit`):

- **Incremental**, at write time, on the module's own transaction:
  `services.search.upsert(tx, ctx, module, entries)`,
  `replace(tx, ctx, module, kind, refId, entries)`, `remove(tx, ctx, module, { kind, refId, part? })`.
  - `upsert` inserts or overwrites each (module, kind, refId, part) — other parts of the ref are
    untouched; duplicate keys within one call collapse to the last.
  - `replace` deletes *every* part of (module, kind, refId) then inserts `entries`, which must all
    be that kind and refId (else `SearchEntryError`). `replace(…, [])` is a remove.
  - `remove` deletes all parts, or one when `part` is given. Idempotent.
  - `moveAclPath(tx, ctx, module, from, to)` re-paths every `resource` entry at or under the
    ltree `from` to the same place under `to`, in one SQL statement — no body is read or
    rewritten. For subtree moves (the data room's folder move): the path changes in the move's
    own transaction, because a stale path is an ACL leak (RLS and `authz.check` evaluate it).
  - `clearBodies(tx, ctx, module, kind, refIds)` empties the body of every part of those refs
    (title and ACL kept): text that must stop being searchable now (the data room turning
    `allowUnscanned` off).
  - `requestReindex(tx, ctx, module)` for bulk changes nothing above expresses: stamps
    `search_state.requested_at` (the database clock; the latest request is kept) and enqueues
    `search.reindex` in the same transaction.
  - Every write takes the module's index lock (`pg_advisory_xact_lock_shared` on
    `search:<ws>:<module>`) until the caller commits. Writers never wait for one another; they
    wait for at most one page of a running rebuild.
  - They need a **staff or system** context (RLS gives investors read access only); an external or
    view-as context throws `SearchEntryError` before touching the database. Index investor-caused
    changes from a job or subscriber under `systemContext(workspaceId)`.
  - A malformed entry throws `SearchEntryError` naming module, ref and field: kind
    `^[a-z][a-z0-9_-]{0,63}$`, refId a uuid, part ≤ 128 characters, title/body strings, `href` an
    SPA path with exactly one leading `/` (no scheme, host, backslash, whitespace or control
    characters, ≤ 2 048), ACL shape (non-empty uuid `groupIds`; `resourceKind`/uuid
    `resourceId`/ltree `path`), a valid `updatedAt`. **Text never throws** (it is what users
    typed, and the write runs inside their transaction): control characters become spaces, the
    title is cut to 1 000 and the body to 200 000 characters, and a title with nothing left after
    cleaning is stored as `SEARCH_UNTITLED` (`"—"`, U+2014) — the SPA may show a localised
    "Untitled" for a hit whose title is exactly that.
- **Full rebuild**: `search: { version, entries({ tx, ctx }), page?({ tx, ctx, cursor }) }`.
  `entries` yields everything the module wants indexed for `ctx.workspaceId` (an async iterable is
  streamed; an array is fine for small sets) and runs in ONE transaction. A module with many or
  large entries also implements `page`, which the rebuild then uses instead: one bounded page per
  short transaction, `{ entries, next }` with an opaque keyset cursor (`null` = done). Both read
  through `tx` only. Bump `version` to rebuild every workspace after a deploy.

Modules switched off for a workspace are still indexed; the query filters them, so switching one
back on needs no rebuild.

## Reindex and sweep (kernel jobs, `container.ts`)

- `search.reindex { workspaceId, module }` — a series of short system-context transactions, one
  connection at a time, so a rebuild of a large data room never blocks renames, moves or ingest:
  1. **start**: skipped for deleted/purged workspaces; take the module's index lock exclusive and
     read the rebuild's generation `G = clock_timestamp()`;
  2. **pages** (`page`, or the whole `entries` stream in one transaction): each takes the lock
     exclusive, reads its page through its own tx, upserts it in batches (200 rows or 2 M body
     characters per statement; `indexed_at = clock_timestamp()`). Nothing is deleted up front, so
     entries stay searchable throughout;
  3. **end**: lock exclusive, delete the module's entries with `indexed_at < G` (touched by
     neither a page nor a writer since the start — what the provider no longer yields), record
     `search_state` (version, `indexed_at`; `requested_at` cleared only if older than `G`).

  *Ordering.* A page reads the source and writes the index under the exclusive lock; writers hold
  it shared until they commit. So a writer's index write either committed before the page (the
  page, reading after it, sees the writer's source too) or waits for the page and then overwrites
  with its own newer data — a page never overwrites a newer write with older data, and a writer's
  row (stamped after `G`) survives step 3. `source_updated_at` is NOT used for this: a change that
  does not bump it (a path move, a policy toggle) would otherwise be lost or never applied.
  Likewise a `requestReindex` is stamped under the shared lock, so one stamped before `G` was
  committed before `G` and is covered; a later one survives the rebuild. Two rebuilds of one pair
  may interleave safely (each deletes only rows older than its own `G`; the later one re-stamps
  every live row). A module that no longer declares `search` has its entries and state removed.
  An invalid provider entry is logged (`search.entry_invalid`) and skipped rather than failing the
  module. Queue policy `short`, key `search:<ws>:<module>`: at most one queued job per pair.
- `search.sweep` (cron `*/10 * * * *`) — lists live workspaces in host context and, per
  workspace under `systemContext`, enqueues a rebuild where state is missing, built at another
  version, or `requested_at` is set (plus clean-up for state of modules that no longer index).
- CLI: `fundroom search reindex [--workspace <slug|id>] [--module <id>]` runs the same rebuild
  synchronously in the CLI process (no worker needed), prints one line per pair and records
  `search.reindex_requested` on the platform audit chain. A pair that fails is printed as
  `<ws>\t<module>\tfailed\t<message>`; the command carries on and exits 1.
- Workspace purge deletes the workspace's `search_entry` and `search_state` rows in the purge
  transaction.

## Limits

| | |
|---|---|
| body | 200 000 characters (truncated on a code-point boundary) |
| title | 1 000 characters (truncated) |
| query | 1–200 characters, ≤ 12 whitespace-separated words, ≤ 32 lexemes |
| page | `limit` 1–50 (default 20), `offset` 0–500 |
| candidates per search | 1 000 rows |
| snippet | 2 fragments, ≤ 480 characters |
| rate | 30 searches / minute / membership |
