Release images: merging the "version packages" PR now tags `v<version>` (from `apps/server/package.json`, one tag for the fixed core group, on the exact commit the image is built from), creates a draft GitHub release from the server CHANGELOG, and runs the image job, which previously never ran because every package is private and `changeset publish` published nothing. The image index is pushed untagged, scanned (Trivy), signed and attested, and only then tagged: `X.Y.Z`; `X.Y`, `X` (not for 0.x) and `latest` only for a version with no prerelease part that is the highest in that line, so a release candidate or a backport never moves them. `X.Y.Z` never moves to another digest (a re-run that rebuilt the image fails instead). The release is published, with its SPDX SBOM attached, after the image is tagged. A release whose tag step or image failed resumes on the next run of the tag's commit. The OCI `org.opencontainers.image.version` label now carries the release version (`<version>+git.<sha7>` on `edge`) through the `FUNDROOM_VERSION` build argument. CI refuses a changeset that names no package of the fixed group (it would release nothing). Nothing is published to npm.
